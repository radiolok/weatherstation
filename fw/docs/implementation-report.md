# Отчёт о реализации прошивки (F0–F11)

Ветка `fw/impl` от `fw/plan`. Фазы F0–F10 плана [`implementation-plan.md`](implementation-plan.md) выполнены без железа, F11 — документация и артефакты CI. Проверки на плате H1–H19 не выполнялись: для них есть тесты в `fw/tests/hw` и команды оболочки.

Главное ограничение: в песочнице не было доступа к PyPI, поэтому не удалось поставить `west`, twister и `pytest-twister-harness`, и ни одна сборка Zephyr здесь не запускалась. Первые настоящие сборки для `native_sim` и ESP32-S3 сделает CI. Что проверено локально и чем — в разделе [«Что проверено где»](#что-проверено-где).

## Как устроено

- **`fw/lib/`** — вся логика на чистом C без Zephyr. Сюда входят кодер Mobitec и шрифты, JSON, хранилище переменных, компилятор и сериализатор набора экранов, рендерер, правила выбора экрана, обработка датчиков, автомат кнопки и LED, автомат сети, POSIX TZ и солнце, MQTT/HA, настройки, отображение METAR и автомат OTA. Всё покрыто ztest. Единственный файл на C++ — адаптер `metar_cpp`.
- **`fw/src/`** — сервисы Zephyr. Они только связывают `lib/` с драйверами, zbus, сетью и оболочкой. Каждое действие сервиса доступно командой `ws …`, и тесты на `native_sim` управляют устройством так же, как человек на стенде.
- **`fw/emul/`** — эмуляторы BME280 (`i2c-emul`) и MH-Z19B (`uart-emul`) и снифер табло. Они стоят за теми же алиасами devicetree, что и железо.
- **`fw/web/`** — веб-страница без сборки: `index.html`, `app.js`, `render.js`, `style.css`. В прошивку она попадает в gzip. `render.js` — браузерный двойник `lib/screens/render.c`, и оба проверяются одними эталонными кадрами.

## Что проверено где

**В песочнице:**

- Все наборы ztest на ПК с ASan/UBSan, через шим `fw/tests/host` — 14/14. Метеосводки идут через настоящий `metar_cpp`.
- Тесты node: 8/8.
- Playwright против макета: 12/12. Макет использует хостовую сборку `lib/` (`build/host/wsapi`), поэтому проверка набора экранов настоящая.
- Clang-format и актуальность сгенерированных файлов (`lint.sh`).
- Для `native_sim` и ESP32-S3, в том числе с `overlay-smp.conf`, конфигурация Kconfig разрешается без предупреждений, а devicetree собирается скриптами самого Zephyr (`gen_edt`, `gen_defines`).
- Каждый файл `fw/src`, `fw/emul` и адаптер METAR проходит `gcc -fsyntax-only -Wall` с заголовками, сгенерированными для каждой платы: хостовый gcc для `native_sim`, xtensa-gcc из Zephyr SDK 0.17.4 для ESP32-S3.

**Только в CI**, локально не запускалось из-за отсутствия `west`:

- Компоновка прошивки.
- Twister.
- Интеграционные тесты на `native_sim`.
- Playwright против `native_sim`.
- Сборка ESP32-S3 с MCUboot и подписью.

Ошибки уровня компоновщика и поведения во время работы сначала проявятся здесь.

**Итог CI на PR #2:** все задачи зелёные: lint, host, unit, golden, integration, web, target, size.

## Что нашёл CI

Первые настоящие сборки и прогоны выявили ошибки. Все исправлены в ветке.

**Прошивка:**

- **Порча списка таймаутов ядра.** Первая загрузка экранов публикует `ws_chan_cfg`. Слушатель дисплея перепланировал свою задачу ещё до `ws_display_start()`, а `k_work_init_delayable()` затем инициализировал уже запланированный элемент. После этого таймауты переставали срабатывать: «зависала» консоль, не стартовал поток датчиков.
  - Исправление: задачи дисплея, часов и сохранения лампы объявлены статически через `K_WORK_*_DEFINE`.
- **`eventfd()` хоста на `native_sim`.** С библиотекой C хоста (`CONFIG_NATIVE_LIBC`) Zephyr не собирает `lib/posix`, поэтому HTTP-сервер получал дескриптор хоста. Когда номер совпадал с принятым сокетом, NSOS завершался с «EPOLL_CTL_ADD: errno=17».
  - Исправление: обёртки в `fw/src/net/eventfd_native.c`.
- **SMP по UDP.** Транспорт Zephyr ждёт в блокирующем `recvfrom()`. NSOS при этом держит блокировку дескриптора, и ответ уходил только со следующим запросом.
  - Исправление: свой транспорт `fw/src/ota/smp_udp.c`: ожидание в `poll()`, чтение без блокировки.
- **Синхронизация с интернетом в тестах.** NTP по умолчанию (`pool.ntp.org`) на `native_sim` блокировал всю симуляцию в `getaddrinfo()` хоста и перезаписывал часы тестов.
  - Исправление: Kconfig `WS_NTP_DEFAULT_SERVER`, на `native_sim` пустой.
- **Нехватка DRAM на ESP32-S3.** Большие буферы вынесены в PSRAM (`WS_BIG_BSS`), там же куча mbedTLS и буферы Wi-Fi.
- **Прочее.** Исправлены:
  - разбор контрольной суммы Mobitec;
  - «нулевой» sha256 OTA;
  - `Content-Length` при загрузке через веб;
  - `/api/glyphs`;
  - TLS на стеке оболочки;
  - сеть, которая не выходила в online;
  - секция ресурсов HTTP;
  - `strdup`/`strtok_r` в `metar_cpp`.

**Тестовая обвязка:**

- Ожидание подписок MQTT и порта HTTP.
- Ввод в консоль кусками, без потери строк лога.
- При зависании печатаются стеки всех потоков из gdb (`WS_GDB=1`) и вызовы сокетов из strace (`WS_STRACE=1`) — оба включены в CI.

## Отступления от плана и решения

- **Кнопка.** Вместо `zephyr,input-longpress` — автомат `lib/ui` поверх `gpio-keys`: нужны «зажата при старте» и тесты дребезга без железа.
- **Табло.** Вместо UART async API — поток передачи с `uart_poll_out`: одинаково работает на `uart-emul` и ESP32.
- **Эмулятор BME280** свой: в Zephyr 4.3 его нет.
- **Сканирование Wi-Fi** до запуска точки доступа, список кешируется. Работает ли скан в режиме AP+STA, покажет H13.
- **MCUmgr** вынесен в `overlay-smp.conf`, потому что он без аутентификации. Сборка для `native_sim` в CI включает его для теста `smpclient` (echo). Группа образов (`overlay-smp-img.conf`) собирается только на плате: `img_mgmt` требует `CONFIG_FLASH_LOAD_OFFSET`, которого у `native_sim` нет; загрузка через `smpmgr` — H16.
- **Сроки действия сертификатов** METAR не проверяются (`MBEDTLS_HAVE_TIME_DATE` выключен), см. «Открытые вопросы» в плане.
- **Загрузка образа со страницы** без sha256, если браузер не в защищённом контексте. Подпись MCUboot проверяется всегда.
- **Mosquitto в CI** запускается через `docker run` с файлом конфигурации.
- **Мелкие решения в коде:**
  - токены JSON с 16-битными смещениями (документ до 64 КБ, 10 байт на токен);
  - числа везде в десятых долях, округление как `Math.round` в JS — чтобы C и браузер рисовали одинаково;
  - новое правило экрана в редакторе создаётся сразу валидным (окно 07:00–08:00);
  - при самопроверке уже подключённый брокер засчитывается сразу.

## Безопасность

- Секретов в репозитории нет.
- Ключ подписи MCUboot — сгенерированный тестовый, отмечен в имени файла и в `fw/keys/README.md`. Боевой ключ задаётся при сборке (`SB_CONFIG_BOOT_SIGNATURE_KEY_FILE`) и не коммитится.
- Пароль веб-страницы хранится как соль + SHA-256.
- Секреты не отдаются ни через API, ни через MQTT: вместо них приходят флаги `*_set`.
- Сервер METAR и загрузка OTA по `https://` проверяются по корневым сертификатам.

## Проверки на железе H1–H19 — не выполнены

Тесты в `fw/tests/hw/test_hw.py` автоматически делают то, что доступно из консоли, а измерения и осмотр спрашивают у оператора (`--hw-operator -s`; без флага такие шаги пропускаются с описанием процедуры). С `--sign-port` кадры на линии принимает виртуальное табло — USB-RS485 адаптер и снифер, см. [стенд с виртуальным табло](bench-virtual-sign.md).
