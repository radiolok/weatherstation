# weatherfeed

Сервис прогноза для домашнего сервера. Опрашивает несколько погодных источников, выбирает для каждой переменной значение по таблице приоритетов и публикует готовый прогноз в MQTT для метеостанции. Интерфейс — плагин Cockpit, отдельный веб-сервер не нужен.

![Источники прогноза](../../docs/img/system-forecast-sources.svg)

Код пока не написан, ниже описано устройство.

## Состав

```
/etc/weatherfeed/
  config.yaml            координаты, ключи API, MQTT, таблица приоритетов
  sources/yandex.py      def fetch(ctx) -> dict
  sources/gismeteo.py
  sources/metar.py       METAR и TAF ближайшего аэропорта
  derive.py              def derive(vars) -> dict: гололёд, окно осадков
/var/cache/weatherfeed/  последний сырой ответ каждого источника
/usr/local/bin/weatherfeed
/usr/share/cockpit/weatherfeed/   плагин: manifest.json, index.html, JS
weatherfeed.service, weatherfeed.timer
```

## Как работает

1. systemd-таймер раз в 10 минут запускает `weatherfeed run`.
2. Каждый источник, у которого подошёл срок, запускается отдельным процессом с таймаутом 30 с. У источника свой период и суточный лимит: Яндекс — раз в 40 минут, не больше 50 запросов в сутки.
3. Сырой ответ сохраняется в кэш, поэтому новый парсер можно прогнать по нему без нового запроса.
4. Для каждой переменной берётся свежее значение из источника с наивысшим приоритетом. Если источник упал или значение устарело, берётся следующий.
5. `derive.py` вычисляет составные признаки, например гололёд по METAR, TAF и прогнозу.
6. Итог публикуется в `ws/<id>/forecast` с флагом retain. В поле `src` указано, откуда взята каждая переменная.

Формат сообщения описан в [`fw/README.md`](../../fw/README.md#mqtt-и-home-assistant).

## Страница в Cockpit

Плагин без своего бэкенда: файлы читаются и пишутся через `cockpit.file()`, раннер запускается через `cockpit.spawn()` с потоковым выводом.

- **Источники.** Список со статусом и счётчиком запросов за сутки, редактор скрипта, под ним консоль. Кнопки «Запросить и разобрать», «Разобрать сохранённый ответ», «Сохранить».
- **Переменные.** Строки — переменные, столбцы — источники, в ячейке приоритет «—, 1, 2, 3» и текущее значение. Источник, который сейчас используется, выделен.
- **Итог.** JSON для табло и кнопка «Опубликовать сейчас».

Журнал запусков таймера виден в разделе Cockpit «Службы». Редактор кода лежит в папке плагина: Cockpit не загружает внешние CDN.
